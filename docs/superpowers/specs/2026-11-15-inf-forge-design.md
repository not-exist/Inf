# Inf 锻刀核心 设计文档

- 日期：2026-11-15
- 状态：待批准
- 仓库：`git@github.com:not-exist/Inf.git`（该远程目前不存在，推送前需先创建或替换地址）
- 目标版本：Minecraft 1.21.1 / NeoForge 21.1.x / Java 21

## 1. 意图与为什么

复刻 ForgeTax（GraveYardDev，2026-09-29，Steam）的核心决策循环：**每一锤都同时提高刀的价值和碎裂风险，玩家自己决定什么时候停手**。不是做一套新的打铁模拟，也不是加几把数值更高的刀，而是让"贪与止损"成为 MC 里可反复玩的锻造仪式。

本阶段只做锻刀核心。龙贡（周期交贡、龙失去耐心）和遗物机（用刀换遗物/抽票）明确不做，但数据结构和交互入口要留出扩展位。

## 2. 目标 / 非目标

**目标**

- 一个锻刀台方块，放入刀胚与锤子，在 GUI 内逐次"锻打"。
- 价值随成功锻打上升，碎裂风险随价值与锻打次数上升；失败刀胚直接消失。
- 随时"停手入库"，按最终价值结算阶位，产出带属性、阶位名与阶位外观的武器。
- 五种武器：剑、镐、斧、镰刀、匕首，各有明确的属性差异。
- 每次锻打消耗锤子 1 点耐久；锤子配方 = 铁块 + 烈焰棒。
- 同一类武器完成 10 把后充能 Frenzy，可在短窗口内无碎裂风险连锤。
- 服务端权威，单人/多人同一套逻辑；所有 RNG 在服务端。

**非目标（本阶段）**

- 龙贡、龙的耐心、遗物机、抽票、永久死亡/局外成长。
- 控温、角度、节奏等第一人称物理锻打（已选全 GUI 决策）。
- 生存材料链（采矿→冶炼→制胚）；v1 直接用铁锭合成刀胚。
- 自定义维度、锻造厅结构、任务线、JEI 联动。
- 材质分级（铜/铁/钢/秘银）；v1 只有铁系胚。

## 3. 核心循环

```
铁锭+木棍 → 刀胚 ──放入锻刀台──> [锻打] ──成功──> 价值↑ 风险↑
                                   │                    │
                                   │                    ├─[继续锻打]
                                   │                    ├─[停手入库] → 成品武器（阶位/属性/名字/外观）
                                   └──失败──> 刀胚碎裂（全部投入消失）
锤子：每次锻打 -1 耐久；耐久归零锤子消失
Frenzy：同类武器完成 10 把 → 下一次锻造窗口内 3 锤不会碎
```

一把刀的"局"就是一次放入到停手/碎裂之间。没有跨刀的整体 run；风险只累积在当前刀胚上，停手即锁定收益。

## 4. 数值模型

锻造数值集中在 `ForgeBalance`，默认值如下（可被服务端配置覆盖）；锤子耐久为固定常量，v1 不做配置：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `baseRisk` | 0.015 | 第一次锻打的基础碎裂率 |
| `riskPerStrike` | 0.0014 | 每次锻打增加的碎裂率 |
| `riskPerValue` | 0.00003 | 每点价值增加的碎裂率 |
| `maxRisk` | 0.85 | 碎裂率上限 |
| `baseGain` | 12 | 单次锻打基础价值增益 |
| `gainPerStrike` | 1 | 每 2 次锻打额外 +1，最多 +10 |
| `gainVariance` | 8 | 随机浮动 0–8 |
| `minGain` | 4 | 单次最小增益 |
| `frenzyRequired` | 10 | 充能所需同类成品数 |
| `frenzyFreeStrikes` | 3 | Frenzy 窗口内免碎锤数 |
| `strikeCooldownTicks` | 4 | 两次锻打的最小间隔 |

公式（纯函数，便于单测与模拟）：

```
gain = max(minGain, baseGain + min(strikes / 2 * gainPerStrike, 10) + gainRoll * gainVariance / 100)
break = min(maxRisk, baseRisk + riskPerStrike * strikes + riskPerValue * value)
damage = (1 - break) * 0.08
great  = (1 - break - damage) * 0.15
success = 1 - break - damage - great
```

- `gainRoll ∈ [0, 99]`，`outcomeRoll ∈ [0, 1)`；按 `break → damage → great → success` 的区间顺序判定。
- 一次锻打有四种结果：
  - **破坏 BREAK**：刀胚销毁，风险最高。
  - **损伤 DAMAGE**：刀保留，损失 10% 当前价值（至少 1），锻打次数 +1。
  - **成功 SUCCESS**：获得正常增益，次数 +1。
  - **大成功 GREAT_SUCCESS**：获得双倍增益，次数 +1。
- Frenzy 生效时 `break = damage = 0`，`success = 75%`、`great = 25%`。
- 典型到达次数约 6/13/22/34/47 锤；传说单局成功率约 5%，由 `./gradlew balanceSim` 的蒙特卡洛模拟验证。
- 所有四个概率都通过 `ContainerData` 下发并在 GUI 右侧实时列出，客户端不自行计算。

### 阶位阈值

| 阶位 | id | 最低价值 | 显示名 |
|---|---|---:|---|
| 0 | `crude` | 0 | 粗制 |
| 1 | `common` | 100 | 寻常 |
| 2 | `fine` | 240 | 精良 |
| 3 | `rare` | 450 | 稀有 |
| 4 | `epic` | 720 | 史诗 |
| 5 | `legendary` | 1000 | 传说 |

停手时价值为 0 视为取消，刀胚原样退回；价值 > 0 一律按上表结算，最低为粗制。

## 5. 武器类型与属性

五种武器共用一套"刀胚 → 成品"流程，差异在基础属性表与少量行为。

| 类型 | 定位 | 关键属性 |
|---|---|---|
| 剑 `sword` | 均衡 | 伤害中、攻速中、横扫 |
| 镐 `pickaxe` | 采集 | 伤害低、挖掘速度与挖掘等级随阶位 |
| 斧 `axe` | 重击 | 伤害高、攻速低、可去皮 |
| 镰刀 `scythe` | 范围 | 伤害中高、攻击距离 +0.5~+1.5、横扫比例高 |
| 匕首 `dagger` | 速攻 | 伤害中、攻速高（2.5–3.0）、攻击距离 -1.0~-0.5、无击退、无横扫 |

属性以 `WeaponStatsTable.forTier(kind, tier)` 的纯数据表给出；成品生成时把数值写入 `ATTRIBUTE_MODIFIERS` 数据组件，不依赖物品类里的固定阶位。列顺序为阶位 0→5（粗制→传说）：

| 类型 | 伤害 | 攻速修正 | 攻击距离修正 | 横扫比例 | 挖掘速度 | 挖掘等级 |
|---|---|---|---|---|---|---|
| 剑 | 4,5,6,7,9,11 | -2.4,-2.4,-2.3,-2.2,-2.1,-2.0 | 0 | .50,.55,.60,.65,.70,.80 | 0 | 0 |
| 镐 | 2,3,4,5,6,8 | -2.8,-2.7,-2.6,-2.5,-2.4,-2.3 | 0 | 0 | 4,6,8,10,12,15 | 1,2,2,3,3,4 |
| 斧 | 6,7,8,10,12,15 | -3.0,-3.0,-2.9,-2.8,-2.7,-2.6 | 0 | 0 | 4,6,8,10,12,15 | 1,2,2,3,3,4 |
| 镰刀 | 5,6,7,9,11,13 | -2.6,-2.6,-2.5,-2.4,-2.3,-2.2 | +.50,+.50,+.75,+1.0,+1.25,+1.5 | .80,.85,.90,.95,1.0,1.2 | 0 | 0 |
| 匕首 | 3,4,5,6,8,10 | -1.5,-1.4,-1.3,-1.2,-1.1,-1.0 | -1.0,-.9,-.8,-.7,-.6,-.5 | 0 | 0 | 0 |

攻速是相对玩家基础 4.0 的加法修正（例如匕首传说 = 3.0 次/秒）；攻击距离是相对基础 3.0 格的修正；挖掘等级 4 对应钻石级。

关键实现约束：

- 攻速/伤害/攻击距离（`entity_interaction_range`）/横扫（`sweep_damage_ratio`）均用属性修饰符。
- 匕首无击退：监听 `LivingKnockBackEvent`，攻击者为手持匕首的玩家时把强度设为 0（含冲刺击退）。
- 镐/斧的挖掘速度与"能否正确掉落"由物品类重写 `getDestroySpeed` / `isCorrectToolForDrops`，读取刀身上的阶位。
- 剑与镰刀继承原版剑类的横扫判定；匕首把横扫比例设为 0。

## 6. 锻造台与 GUI

方块 `inf:forge_table`（锻刀台），右键打开 GUI。三个槽位：

1. 刀胚槽（只接受对应模组的 5 种刀胚）
2. 锤子槽（只接受 `inf:hammer`）
3. 产出槽（只出不进）

GUI 采用全屏暗色锻造场景 + 居中 420×260 大面板（含义上的“铺满屏幕”），左侧为铁砧/槽位，中间为刀身与价值，右侧实时列出四种结果概率：

```
┌──────────────────────────────────────────────┐ 420×260，全屏暗底+居中面板
│ 锻 刀 台       贪念与止损          INF FORGE │
│ ──────────────────────────────────────────── │
│ ┌─────┐  精良 · 长剑          结果概率        │
│ │ 刀胚│  价值 268             破坏   9.7% ▰▰  │
│ └─────┘  ▰▰▰▰▰▰▱▱▱▱ 阶位     损伤  11.2% ▰▰  │
│ ┌─────┐  已锻 15 次            成功  62.4% ▰▰ │
│ │ 锻锤│  下一锤 +18 ~ +26      大成功 16.7% ▰ │
│ └─────┘  狂热 8/10              ▰▰▰▰▰▰       │
│ ┌─────┐                                     │
│ │ 成品│  [   锻 打   ] [停手] [狂热]         │
│ └─────┘       玩家背包 3×9 + 快捷栏          │
└──────────────────────────────────────────────┘
```

- **锻打**：服务端校验槽位与锤子耐久 → 扣 1 耐久 → 按四种结果结算（破坏/损伤/成功/大成功）→ 更新刀身组件或清空刀胚。两次锻打至少间隔 `strikeCooldownTicks`。
- **停手入库**：产出槽必须为空；按价值结算阶位，生成成品；刀胚消耗；同类成品计数 +1。
- **Frenzy**：仅在已充能且刀胚价值 > 0 时可用；激活后该刀后续 3 次锻打免碎，GUI 显示剩余次数。
- 按钮走原生 `AbstractContainerMenu#clickMenuButton`（`0=锻打, 1=停手, 2=Frenzy`），不新增自定义网络包。
- 破坏锻刀台时掉落三个槽位内的全部物品。

## 6.2 进度分支

新增 19 个原版风格进度，树形结构与触发条件见 `docs/advancement-tree.md`：根节点（获得锻锤）→ 第一锤 → 出鞘；出鞘分三条支线：阶位（寻常→精良→稀有→史诗→传说）、兵器（剑/镐/斧/镰/匕→兵器谱）、狂热；第一锤另有碎锋、锤之终、裂痕、大成功。全部用 `minecraft:impossible` 判定，由服务端在对应事件发生时授予，避免客户端伪造。

## 7. 刀胚、成品与命名

- 刀胚：`inf:sword_blank`、`pickaxe_blank`、`axe_blank`、`scythe_blank`、`dagger_blank`，用铁锭 + 木棍合成。
- 成品：`inf:forged_sword`、`forged_pickaxe`、`forged_axe`、`forged_scythe`、`forged_dagger`。
- 刀身状态用数据组件 `inf:blade_data = {kind, value, strikes, seed}`，随物品持久化并网络同步。
- 成品名字：`<阶位名> · <类型名>`，例如"精良 · 长剑"；使用可翻译组件，zh_cn/en_us 双语。
- 外观：按阶位给整件物品染色（客户端 `ItemColor` 读取 `blade_data` 的阶位），六档调色板：灰、铁白、钢蓝、紫、金、绯红。后续可无痛替换为每阶位独立模型。
- 稀有度组件随阶位提升（COMMON → EPIC），Tooltip 显示价值、锻打次数、阶位。

## 8. 锤子经济

- `inf:hammer`，耐久 128（固定常量；物品最大耐久在注册时确定，v1 不做配置）。每次"锻打"消耗 1 点；最后 1 点使用时仍正常结算本次锻打，随后锤子损坏。
- 配方：无序合成，1 铁块 + 1 烈焰棒。
- 锤子不可堆叠，不可作为武器，附魔能力为 0；后续可扩展多档锤子，v1 只做一把。

## 9. 多人 / 权威 / 存档

- 所有锻打判定、阶位结算、碎裂、Frenzy 充能均在服务端完成；客户端只发按钮 id。
- 刀身状态跟随物品组件；锻刀台槽位存在方块实体并写入区块存档。
- Frenzy 计数是玩家级数据，用 NeoForge `AttachmentType` 持久化并 `copyOnDeath`。
- 配置为服务端配置；风险/增益的显示值通过 `ContainerData` 下发，避免客户端配置不一致导致显示错误。

## 10. 取舍与风险

- **全 GUI 决策**牺牲了第一人称锻打的手感，换来可测试、可平衡、可快速迭代。世界内表现（铁砧音效、火花粒子、方块动画）作为风格补偿。
- **风险曲线**是唯一的核心难度来源，必须用蒙特卡洛模拟调参，不能凭感觉写死。
- **属性组件**方案让同一物品承载六档强度；若后续需要每阶位独立物品（如不同耐久/附魔），需要迁移，但组件里已有 seed 与阶位，迁移成本可控。
- **匕首无击退**依赖 `LivingKnockBackEvent`；若该事件在某些版本不覆盖冲刺击退，再退化为 Mixin，v1 先按事件实现。
